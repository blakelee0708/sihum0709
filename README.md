# 시험사주

생년월일과 시험 정보를 입력받아 사주 기반의 시험 대비 운세와 준비 가이드를
제공하는 모바일 웹서비스입니다.

기존 사주 서비스가 생년월일만 받는 것과 달리 **시험명, 시험 날짜, 시험 방식,
시작 시간을 함께 받아 계산에 직접 사용합니다.** 그래서 시험 전 7일 기운 흐름,
사용자에게 유리한 시험 방식, 시작 시간 궁합 같은 항목이 나옵니다.

---

## 실행

```bash
npm install
npm run dev
```

http://localhost:3000 에서 열립니다. `/start`부터 보시면 흐름 전체를 볼 수 있습니다.

`.env.local`이 없어도 목업 모드로 동작합니다. 로그인과 유료 리포트를 보시려면
`.env.example`을 복사해 값을 채우십시오.

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발 서버 |
| `npm run build` | 프로덕션 빌드 |
| `npm test` | 테스트 (만세력 검증 포함) |
| `npm run typecheck` | 타입 검사 |

## 만세력 계산

`lib/saju/`가 이 서비스의 핵심입니다. 계산 규칙은 아래로 확정되어 있습니다.

| 항목 | 처리 | 적용 대상 |
|---|---|---|
| 경도 보정 | 30분을 뺍니다 | **시주만** |
| 서머타임 보정 | 시행 기간이면 60분을 더 뺍니다 | **시주만** |
| 절기 경계 | 보정하지 않은 **원본 시각**으로 비교 | 년주, 월주 |
| 일주 | **원본 날짜** 기준 경과일 | 일주 |
| 자시 | 23:00-23:59는 당일 유지 (조자시) | 일주 |
| 오행 강약 | 일간 3, 월지 3, 나머지 각 1. 지장간 미반영 | 오행 분포 |

절기 테이블이 KST 기준이라 보정한 시각을 맞대면 기준이 섞입니다. 그래서 절기
경계는 원본 시각으로 봅니다. 반면 시지는 실제 태어난 시각을 묻는 자리이므로
보정을 적용하며, 그 결과 실질 자시 시작이 23:30으로 밀립니다. 의도한 동작입니다.

### 검증 상태

- 절기 시각 — 2024 / 2025 / 2026년 절입 36개가 공표 절기표와 **분 단위까지 일치**
- 일주 기준일 — 1969-01-25 경자일, 1969-02-22 무진일로 교차 확인
- 검증 사례 10건이 기대 결과와 대조되어 `npm test`에서 O/X로 판정됩니다

결과는 `test/saju-output.md`에 표로 출력됩니다. `npm test` 실행 시 다시 생성됩니다.

**명리 해석 관점의 전문가 검토는 아직 받지 않았습니다.** 절기와 일진이라는
입력이 맞다는 것까지 확인된 상태입니다.

### 절기 테이블 다시 만들기

```bash
pip install skyfield
python scripts/gen-solarterms.py
```

1940-2030년 절입 12개를 생성합니다. 첫 실행 시 천체력(DE421, 17MB)을 내려받습니다.
초는 반올림하지 않고 버립니다 — 공표 절기표와 같은 방식입니다.

## 문장 조각

무료 구간은 AI를 쓰지 않습니다. 미리 작성한 문장 조각 177개를 조립합니다.
원가가 0원이고 응답이 즉시이며, 같은 입력에는 항상 같은 결과가 나옵니다.

- 무료 167개 — `lib/content/fragments.json`
- 유료 10개 — `lib/content/paid-fragments.json`
- 조립 규칙과 변수 치환 — [`lib/content/FRAGMENTS.md`](lib/content/FRAGMENTS.md)

조각을 수정하실 때는 `FRAGMENTS.md`의 작성 원칙을 지켜주십시오. 개수와 키는
테스트가 검사합니다.

## 데이터베이스

```bash
supabase db push
```

또는 Supabase 대시보드 SQL Editor에 `supabase/migrations/` 파일을 붙여넣습니다.
여러 번 실행해도 안전합니다.

`reports`와 `payments`는 사용자 정책이 **select 전용**입니다. 사용자가 "결제했다"는
행을 직접 만들 수 없어야 하므로, 이 두 테이블에 쓰는 서버 라우트는 반드시
`createServiceClient()`를 씁니다.

## 아직 안 된 것

| 항목 | 상태 |
|---|---|
| 실제 결제 | **더미입니다.** PG 검증 없이 성공으로 기록하므로 출시 전 반드시 교체 |
| AI 리포트 | `ANTHROPIC_API_KEY`가 없으면 샘플 문구가 들어갑니다 |
| 검색 연동 | 키가 없으면 "확인되지 않음"으로 처리합니다 |
| 카카오 / 구글 로그인 | OAuth 앱 등록 필요. 이메일 로그인은 동작합니다 |
| 카카오 나에게 보내기 | 링크 복사로 대체 중 |
| 관리자 화면 | 미구현 (PRD 22장) |

진행 상황과 판단 근거는 [`PROGRESS.md`](PROGRESS.md)에 있습니다.
