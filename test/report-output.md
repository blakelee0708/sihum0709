# 리포트 생성 실측 — effort 도입 후

모델 `claude-sonnet-5` · `max_tokens` 32000 · 원가는 백만 토큰당 입력 $2 / 출력 $10, 환율 1,400원 (PRD 8.13)

목표는 **필기 120초 이내 150원 이내**, **면접 160초 이내 220원 이내**입니다.

출력 토큰에는 thinking 분량이 포함됩니다. 시간과 원가의 병목은 검색이 아니라
이 thinking이고, Sonnet 5에서 그것을 조절하는 수단은 `output_config.effort`
하나입니다. `thinking.budget_tokens`는 이 모델에서 400입니다.

원본은 `report-output-round1.md`(필기 low / 면접 medium)와
`report-output-round2.md`(둘 다 low)이고, 생성 본문 전문은
`report-output-body-round1.md` · `report-output-body-round2.md`입니다.

`low`에서 섹션 하한 미달이 늘어납니다. 합계는 하한의 98퍼센트라 실패
임계(하한의 70퍼센트, `lib/ai/length.ts`)와는 멀지만, 섹션 단위로는 절반
이상이 하한을 밑돕니다. **effort를 올려 해결할 문제가 아니라 프롬프트로
끌어올릴 문제입니다.** 올려서 맞추면 원가가 두 배가 됩니다.

상한 초과는 거의 한 곳에서만 납니다. 마지막 섹션 `내 사주로 본 시험/면접
전략`(상한 400자)이 성공한 7건 중 6건에서 424~567자로 넘쳤습니다. 이
섹션만 상한을 올리는 편이 맞아 보입니다.

## 4. 생성물 품질 (본문을 직접 읽고 판단)

`low`에서 내용 정확도는 유지됩니다. 계산값이 그대로 본문에 반영됩니다.

| 확인 항목 | low 결과 |
|---|---|
| 오행 수치 | 목 6 · 토 2 · 금 4 · 화 0 · 수 0 (필기), 목4 · 화0 · 토5 · 금2 · 수1 (면접) — 계산값과 일치 |
| 십신 매핑 | 신금 일간 → 관성 화 0점, 식상 수 0점, 비겁 금 4점, 재성 목 6점 — 정확 |
| 12지지 시간대 | 진시 07-08:59 · 사시 09-10:59 · 오시 11-12:59 · 미시 13-14:59 — 정확 |
| 7일 플랜 | D-7~D-day 점수와 관계(아극·상극·상생·비화·설기) 그대로 반영 |
| 궁합 | 삼성전자 토 7 vs 본인 토 5, 주도 관계 — 계산값 반영 |
| 검색 결과 | 인재상 반영, 확인 안 된 것은 "확인되지 않으므로 확정적으로 서술하지 않음"으로 처리 |
| 연간 캘린더 | 월별 점수 반영 |

떨어지는 지점은 두 가지입니다.

1. **분량** — 위 3절.
2. **오행 수치 언급 누락** — 섹션 1~3개에서 수치 없이 "약한 화"처럼만 씁니다.
   `low`뿐 아니라 `medium`에서도 나옵니다 (면접 medium 1회차 2개).

## 5. 잘림 (stop_reason = max_tokens)

**8건 모두 `end_turn`입니다. 자연 발생한 잘림은 0건입니다.**

`low`로 내리면서 출력이 4,400~5,400 토큰으로 줄어 `max_tokens` 32000과는
6배 차이가 납니다. 도입 전 기본 `high`에서는 면접 1건이 32,000에 걸려
잘렸었습니다.

나오지 않는다고 처리가 맞는다는 뜻은 아니라 일부러 만들어 확인했습니다
(`test/truncation.test.ts`, 실제 호출).

```
AI_MAX_TOKENS=2000
→ GenerateError('출력 잘림')
  "max_tokens(2000) · effort low에 걸려 본문이 잘렸습니다"
```

이후 처리는 단위 테스트로 확인했습니다 (`lib/ai/run-report-failure.test.ts`).

| 실패 | reports.status | error_message | retry_count |
|---|---|---|---|
| 출력 잘림 | `failed` | 출력 잘림 | 그대로 |
| 분량 미달 | `failed` | 분량 미달 | +1 |
| 예상 못 한 예외 | `failed` | 알 수 없는 오류 | 그대로 |

`retry_count`가 3 미만이면 `FailedState`가 재시도 버튼을 띄우고,
`/api/report/retry`가 추가 과금 없이 다시 생성합니다.

## 6. effort를 낮춰 새로 생긴 실패와 대응

필기 `low` 1회차가 파싱에서 죽었습니다.

```
Bad control character in string literal in JSON at position 2676
```

모델이 문단을 나누며 문자열 값 안에 줄바꿈을 이스케이프 없이 넣었습니다.
본문은 멀쩡하고 JSON 문법만 어긋난 경우입니다.

`parseSections`가 한 번 실패하면 문자열 안의 제어문자만 이스케이프해서 다시
읽도록 고쳤습니다. 고친 뒤 4건에서 재발하지 않았습니다.
회귀 테스트는 `lib/ai/provider.test.ts`에 있습니다.

## 7. 결정

```
AI_EFFORT_WRITTEN=low
AI_EFFORT_INTERVIEW=low
max_tokens 32000  (그대로)
```

면접을 `medium`으로 되돌리려면 환경변수 한 줄이면 됩니다. 분량 하한 준수가
원가 두 배보다 중요해지는 시점에 그렇게 하십시오.

## 다시 재는 법

```bash
RUN_REPORT_SAMPLE=1 RUNS=2 npx vitest run test/report-output.test.ts
```

`AI_EFFORT_WRITTEN` · `AI_EFFORT_INTERVIEW`로 단계를 바꿔 가며 잽니다.
4건에 약 4분, 실제 과금 약 370원입니다.
